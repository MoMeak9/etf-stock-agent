# ETF/股票自然语言分析 Skill 设计

- 日期：2026-08-10
- 状态：Approved for spec review
- 适用范围：当前 `etf-stock-agent` 仓库的股票、A 股 ETF 和开放式基金分析

## 1. 背景

仓库已经通过 `analyze.py` 提供完整的多标的分析入口，支持自动识别资产类型、1-5 档分析强度、并行分析、日期选择和 Markdown 报告落盘。当前用户需要通过命令行记忆参数并手动启动分析。

本设计增加一个 Codex 个人 Skill，把明确的自然语言分析请求转换为现有 CLI 调用。Skill 不重实现分析逻辑，只负责触发判断、参数解析、命令启动和结果整理。

## 2. 目标与非目标

### 2.1 目标

1. 用户明确提出“分析 DLR”“研究 DLR”“深度分析 DLR”等请求时，自动启动分析。
2. 用户只提到代码、询问价格、新闻或其他非分析问题时，不自动启动。
3. 支持从自然语言中读取标的、分析强度、并行数、日期和资产类型。
4. 未指定参数时使用极致分析和 3 个并行进程，即 `-l 5 -w 3`。
5. 复用 `python3 analyze.py` 的现有进度、错误处理、决策摘要和报告输出能力。
6. 分析完成后向用户返回决策、置信度、风险、耗时和完整报告路径。

### 2.2 非目标

1. 不修改 `analyze.py` 或 TradingAgents 的分析链路。
2. 不在 Skill 中新增数据源、LLM provider 或投资策略。
3. 不把自然语言中的任意股票代码都视为运行指令。
4. 不自动修改 `.env`、安装依赖或替用户补充 API Key。
5. 不把分析结果表述为确定性的投资建议或收益承诺。

## 3. Skill 位置与职责

Skill 安装为 Codex 的个人 Skill：

```text
/Users/minlong_1/.agents/skills/etf-stock-analysis/SKILL.md
```

Skill 的职责边界：

```text
明确自然语言请求
        ↓
触发判断与参数解析
        ↓
拼接 analyze.py 命令
        ↓
在仓库目录启动进程
        ↓
读取终端结果与报告路径
        ↓
整理为用户可读摘要
```

实际分析仍由仓库中的 `analyze.py` 执行。Skill 不调用 API 服务作为默认入口，因为本地 API 服务需要单独启动，且不符合即时分析的默认使用方式。

## 4. 触发规则

### 4.1 必须触发

用户消息同时满足以下条件时才启动：

1. 包含明确的分析意图，例如“分析”“研究”“评估”“复盘”“深度分析”“全面分析”。
2. 包含至少一个可直接传给 `analyze.py` 的股票代码、ETF 代码或交易所 ticker，例如 `DLR`、`AAPL`、`510300`、`008763`。

示例：

```text
分析 DLR
研究 AAPL，给我深度结论
帮我标准分析 510300
复盘 008763，重点看回撤
```

### 4.2 不得触发

以下请求不得自动运行分析：

```text
DLR 是什么公司？
DLR 今天涨了吗？
帮我找 DLR 的新闻
比较 DLR 和 PLD
```

如果用户只提供标的但没有明确的分析意图，应询问其是否需要启动分析。中文公司名、基金名或模糊简称不能直接转换为 CLI 标的；如果没有可靠的 ticker/code，应先询问用户补充代码或市场。

### 4.3 歧义处理

- 没有明确标的：先询问标的。
- 标的无法识别：先询问代码、市场或资产类型。
- 一次请求包含可能混合的股票、ETF 和开放式基金：不要静默拆分或改变用户批次；如果不能确认它们属于同一资产类型，应先要求用户分批运行。
- 用户明确要求运行后，不再额外询问是否确认，直接执行；缺少必要信息时除外。

## 5. 自然语言参数映射

### 5.1 分析强度

默认值为 `-l 5`。

| 自然语言 | CLI |
|---|---|
| 快速扫描、闪电、粗看 | `-l 1` |
| 快速分析、简要分析 | `-l 2` |
| 标准分析、常规分析 | `-l 3` |
| 深度分析、深入研究 | `-l 4` |
| 极致、全面、最高精度、完整研究 | `-l 5` |
| 明确说“强度 N”“级别 N”或 `-l N` | 以明确数字为准 |

如果同一消息同时出现描述词和数字参数，数字参数优先。`-l` 必须是 1-5 的整数；超出范围时先提示用户修正，不启动命令。

### 5.2 并行数

默认值为 `-w 3`。

识别“3 个并行”“3 线程”“并行数 3”“workers=3”等表达，并转换为 `-w 3`。识别“串行”“单线程”“不要并行”时使用 `-w 1`。`-w` 必须是正整数；零、负数或无法解析时先提示用户修正，不启动命令。

### 5.3 日期

识别“截至 YYYY-MM-DD”“分析日期为 YYYY-MM-DD”“看某日数据”等表达，并转换为 `-d YYYY-MM-DD`。未指定日期时不添加日期参数，让 `analyze.py` 使用当天并按项目逻辑回退到可用交易日。

### 5.4 资产类型

- 用户明确说“ETF”时添加 `--asset-type etf`。
- 用户明确说“开放式基金”“公募基金”时添加 `--asset-type fund`。
- 用户明确说“股票”时添加 `--asset-type stock`。
- 未明确指定时使用 `--asset-type auto`，交给现有代码判断。

### 5.5 其他参数

V1 只解析上述核心参数，不解析 provider、模型、后端地址、A 股数据源或 debug 设置；用户提出这些参数时应说明当前 Skill 不代为调整，并建议使用仓库 CLI 的完整参数。默认命令应尽量接近：

```bash
python3 analyze.py <tickers> --asset-type auto -l 5 -w 3
```

## 6. 命令启动约束

1. 工作目录固定为 `/Users/minlong_1/Desktop/Github/etf-stock-agent`。
2. 优先使用仓库现有命令 `python3 analyze.py`，不复制分析逻辑。
3. 多个已确认属于同一资产类型的标的直接作为位置参数传入；混合资产或类型不确定时先询问，不静默拆分。
4. 保留 Rich 进度输出，让用户可以看到分析仍在运行。
5. 不在执行前读取或输出 `.env` 中的密钥。
6. 若 `python3`、依赖、环境变量或外部数据源不可用，停止并返回可操作的错误，不擅自安装或修改配置。

## 7. 结果整理

分析完成后，Skill 应优先从 CLI 输出和生成报告中整理：

- 标的和实际分析日期
- 资产类型
- 操作/基金建议
- 目标价（股票或 ETF 有时提供）
- 置信度
- 风险评分
- LLM/工具调用统计（若 CLI 输出）
- 总墙钟耗时（以 CLI 的 `总墙钟时间` 为准；并行分析不把各标的耗时相加）
- Markdown 完整报告的绝对路径

结果摘要应明确说明这是模型基于当前数据生成的研究结果，并保留报告中的数据缺失和警告，不把缺失数据包装成确定结论。

## 8. 验证标准

Skill 发布前至少验证以下场景：

1. “分析 DLR”能够触发并映射为 `-l 5 -w 3`。
2. “快速分析 DLR，单线程”能够映射为 `-l 2 -w 1`。
3. “深度研究 ETF 510300，3 个并行”能够映射为 `--asset-type etf -l 4 -w 3`。
4. “分析 008763，截至 2026-08-07”能够映射为 `--asset-type auto -l 5 -w 3 -d 2026-08-07`。
5. 仅输入“DLR 今天涨了吗”不会启动 `analyze.py`。
6. 缺少标的或存在混合资产歧义时会先询问。
7. 真实命令失败时，Skill 返回失败原因而不是伪造分析结果。
